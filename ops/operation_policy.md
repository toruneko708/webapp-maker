## 11. ループ脱出ルール（恒久 / 2026-07-30 ユーザー指示）
同じ場所で詰まったら「再試行」ではなく「方針変更」をする。空回りが最も高くつく失敗。
- 同じツール呼び出し / 同じエラーが**連続2回**出たら、3回目はパラメータか手法を変える。
- 同じエラーが**3回**続いたら、そのアプローチを放棄し別経路を取る（パラメータ省略 / 別コマンド / 別ツール / 手順の分割）。
- 「再試行」は方針変更を伴わない限り**1回まで**。
- 実例: `yield_time_ms` が浮動小数点で弾かれ続けた件 → 解決策は「パラメータ自体を省略」。再試行では永遠に直らなかった。
- ループに気づいたら、まず原因を1行で言語化してから動く。原因特定なしの連打は禁止。

## 14. Search Console 所有権確認の分業（2026-07-31）
- **Codexが代行できない唯一の箇所**: Google Search Console へのログイン（Googleアカウントのパスワード・2段階認証・プライバシーを伴うため）。ここは必ずユーザー操作。
- **ユーザーが貼るものは1つだけ**（2方式のいずれか）:
  - HTMLタグ方式: 確認画面の `<meta name="google-site-verification" content="XXXX">` の **XXXX（content値）** をCodexに貼る。
  - HTMLファイル方式: 確認画面が示す **ファイル名（googleXXXX.html）とその中身1行** をCodexに貼る。
- **Codexが受け取って全自動でやること**: index.html の `<head>` 先頭にmetaを挿入（タグ方式）/ または site/ に確認ファイルを配置（ファイル方式）→ Cloudflare Pages へデプロイ → Search Console側で「確認」→ 通ったら sitemap（/sitemap.xml）を送信。ユーザーの次の操作は不要。
- 所有権確認なしでも sitemap は robots.txt 経由で発見されうるが、**確実にクロールを促す＋レポートを見る**には所有権確認が必須。
- 値が来たら即通せるよう、差し込みは apply_patch 1発。デプロイは exec_command。
