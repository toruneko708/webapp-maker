## 1. 趣旨・世界観

- **ブランド名**: 「Webアプリづくり｜判断の順番」。コンセプト＝「正解より、先に何を捨てるか」。
- **ターゲット**: フリーランス / 個人事業主。

- **設計の核＝検証可能性**: AI 判定でなく**ルールベース＋公的リンク**（公正取引委員会 / e-Gov 法令検索）＋免責明記。各チェックに出典条文リンクを直接張る。「このツールが言った」でなく「法がこう言っている、確認しやすくしただけ」。

## 5. 技術的教訓・ハマりポイント

| 事象 | 原因 | 回避策 |
|---|---|---|
| wrangler login が localhost 接続拒否 | リダイレクト先 8976 固定 + Codex exec の受け口が認証前に死ぬ | **ユーザー自身のターミナル**で `npx wrangler login`（ポート指定無効） |
| OAuth トークンで DNS 操作 401 | トークンのスコープに DNS 書き込みなし | DNS はユーザーがダッシュボード手動 or BIND インポート |
| PS 配列 `@(@("a","b"))` の `$p[0]` が文字インデックスに | 配列のネスト展開バグ | ハッシュテーブル配列 `@(@{dir=..;name=..})` or スクリプトファイル化 |
| audit/migrate の配列要素間カンマ抜け | 文字列が 1 文字ずつバラけて map に入る（`s`,`h`,`i`,`t` が MISSING） | 要素間に必ずカンマ |
| JSON-LD 配列要素間カンマ抜け | パースエラー | 要素間に必ずカンマ（apply_patch 追記時に既存末尾カンマ確認） |
| ドメインプロパティの sitemap「無効」 | 相対パス不可・フル URL 必須 | `https://junban.dev/sitemap.xml` で送信 |
| apply_patch で日本語 .ps1 作成 | エンコード壊れ | rg 確認が安全 / 既存ファイルは UTF-8 正しい |
| Get-Content 表示が化ける | 表示エンコードの問題 | ファイル自体は UTF-8 で正しい、apply_patch の context は正確に |
| CRLF 警告 | Git の改行正規化 | **無害**。無視してよい |
| Cloudflare Pages カスタムドメイン API | — | `POST /accounts/{id}/pages/projects/{proj}/domains` body `{"name":"domain"}` |
